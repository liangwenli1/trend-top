# 分类、采集与账户展示修复

基于最新 main `a84637b`。本次沿用黑白蓝、方框控件的现有风格，不访问线上页面，不改线上数据库。

## 定位与取舍

保留六类开源资源、用途筛选、同类对比、Pro 每日摘要与关注列表。用途只描述用户要完成的任务。

- GitHub 并入代码协作；目录、试用并入资源发现；规范并入代码开发。旧筛选链接仍能映射。
- 详情页移除重复的 Category 标签，保留用途、主题和有证据的官方来源。
- 对比表不再默认宣称兼容 Claude、Cursor、Codex 或 shadcn。没有明确来源时显示空缺。
- 进入官方 MCP Registry 只代表被目录收录，不直接等于厂商官方资源。
- 未配置的 Google 登录、邮箱密码的 Enabled 列表和管理员尚未配置支付的技术提示从用户设置中移除。可操作的 Google 关联入口与已关联账户仍保留。
- 套餐 Free / Pro 与邮件开启、暂停、停止分别显示方框状态标签。套餐确认过程中不先宣称 Free；Free 用户即使保存了 active 偏好，也不显示正在发送。

## Use case 筛选为空

两个确定的代码缺陷：旧数据虽能在显示时推断用途，但数据库 use_case 为空；仓库用途筛选原先发生在取出一页数据之后。

现在启动会迁移存量用途，并记录分类版本；仓库用途筛选在计数与分页之前执行。各类型菜单只显示已收录的用途。筛选请求切换时取消旧请求，避免旧响应覆盖新筛选。

搜索、排序、时间窗口、用途在主要筛选区。语言、主题、项目年龄放进更多筛选，并显示已启用的数量。

用途有条目不意味着该用途已有完整增量快照。尚未获得足够历史、安装量或用量时，热度榜仍可能为空；页面提供查看已收录项目的入口，不能把缺失增量伪装成零。

## Skill 数量变化

之前的分类审计将仅在 README 提到 Skill 的整仓库移出 Skill 类型；真正 Skill 必须对应可核实的 SKILL.md。这会减少旧数量，是合理清理，但无法仅凭代码确认线上某次归零的完整原因，仍需 sync_runs / sync_query_stats 和容器采集日志。

本次补强：

1. 发现代码搜索中的 SKILL.md 文件后，补取完整仓库元数据再落库。
2. 目录未匹配条目能按真实 SKILL.md 路径建立独立 Skill，并补充父仓库快照。
3. 文件树使用实际默认分支并尝试 main/master；截断或请求失败记为验证失败。
4. 有限搜索结果中未出现的旧资源不再自动移出目录。分类错误仍可由明确的分类审计处理。
5. 元数据获取失败时保留已有数据，不用 0 Star 或当前日期覆盖未知数据。真实的 0 仍合法。

已验证条目未在本轮重获快照时，历史不会删除，但新窗口的热度仍可能暂缺。此修复不承诺全量覆盖所有热门项目。

## Firecrawl 当前帮助

它在本网站承担补充采集，而不是替代 GitHub：

- 从独立网站来源列表读取标题、简介、图标、Feed / Sitemap 链接等元数据，能处理需要渲染的页面。
- 从 skills.sh、Glama 和官方 MCP Registry 提取条目、关联仓库，以及页面明确展示的安装量、用量、下载量。
- Skill 安装量按名称或精确文件路径匹配。同仓库多个 Skill 时，不把仓库级计数复制给全部 Skill；无法确定归属就不使用该计数。
- 保留来源、采样时间、计数窗口。窗口不明标记 unknown，不宣称是每日使用量。GitHub 更新不会清掉这些补充指标。
- 迁移时撤下旧版无资源归属的 Skill 目录计数，等待重新匹配，不清空项目或其历史。

它不会自动降低 Rankings/Charts 加载时间，不会自动覆盖全网，也不会生成真实访问量。发现覆盖率仍受来源列表、搜索规则、API 配额和验证证据影响。

API 请求格式已对照 [Firecrawl 官方参考](https://docs.firecrawl.dev/api-reference/endpoint/scrape)。本次验证使用隔离数据库与模拟采集结果，未进行付费 Firecrawl 请求或线上覆盖率验证。

## 关注列表

修复公共页面上限 50 导致后续名次缺失、仓库缺少 slug 时误认第一名，以及 GET 提前消耗变化基线的问题。明确使用未筛选的周热度榜；展示后单独确认已查看。操作失败会提示，不假装取消成功。Pro 到期后仍可查看已保存项目并取消关注，但实时名次和变化仍要求 Pro。

## 部署与重新采集

提交、推送这些变更后，在服务器的 trend-top 目录执行：

```sh
git pull
./deploy.sh -d --build
./deploy.sh collect
```

启动会自动补齐用途，无需删除数据库。最后一条会调用实际 GitHub / Firecrawl 服务，耗时与 API 配额相关，可以在采集日志中查看各类失败原因。凭据继续从管理员设置读取，不改为公开环境配置。

Docker scheduler 在 UTC 02:00 后运行每日采集，并恢复错过的任务；邮件任务每小时检查各用户时区与发送时间。完成但部分失败的采集记录 partial，保留有效更新，并避免因可选目录失败每小时重复完整采集；可手动再次采集。
