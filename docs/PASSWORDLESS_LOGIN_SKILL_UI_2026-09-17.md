# 邮箱登录与 Skill 使用界面

## 本次交付

- 邮箱入口统一为 Continue with email；通过六位邮件验证码登录，首次验证后创建账户。
- Google 入口继续保留；两个按钮在真实请求期间显示按钮内的转圈动效并禁止重复操作。
- 去掉注册 / 登录标签、登录密码输入和重复的 Welcome to Trend Top 标题；邮箱占位文案改为 Your email address。
- 验证码支持整段粘贴、数字键盘、焦点移动、60 秒重发倒计时和更换邮箱。验证码有效期十分钟，最多五次验证尝试。
- 移除账户设置中的 Connected accounts 展示。既有 Google 身份记录仍用于登录；未修改 OAuth 身份校验规则。
- 老用户通过同一邮箱进入原账户，保留原密码、语言、付费权益和推送偏好；邮箱验证不会授予 Pro，也不会重新开启已停止的推送。
- 同一仓库展开列表按 Skill 名称组织，多个文件路径显示在同一组中；各路径仍可独立打开原资源详情。
- 使用说明采用等宽字体和深色方框，复制按钮在框内；安装说明仅显示一次，相关资源改为网格卡片。

## 实现范围

新增 `/api/auth/email/request` 与 `/api/auth/email/verify`。验证码使用现有 AUTH_SECRET 的 HMAC 存储，成功消费后删除；数据库条件更新限制错误次数，并发成功验证只允许一次。发送接口按邮箱限频，认证接口沿用每 IP 每小时 30 次限制，拒绝异站 Origin 与非 JSON 请求。

继续使用现有 Resend / SMTP 配置，不需要新增认证供应商或数据库迁移。线上环境须已有 AUTH_SECRET（或既有 ADMIN_TOKEN）和邮件发送配置。Demo 模式只写入本地 outbox，不发送真实邮件。

原密码登录与密码重设 API 保留兼容性；已有密码的用户仍可在账户设置中修改密码。新用户无需创建密码。

未将原来源提供的 `Copy … from …` 文字伪装成可执行 shell 命令；未验证支持的资源不生成 `npx skills add` 命令。

## 验证

新增隔离数据库测试覆盖：验证前不创建账户、会话 Cookie、老账户与 Pro 权益复用、已停止推送保持停止、验证码错误 / 过期 / 耗尽 / 重放、并发发送与消费、重发、用途隔离、Origin / JSON 校验及 IP 限频。

页面检查在代码提交推送后进行，使用本地 Demo 数据，避免修改生产账户或发送真实邮件。记录桌面和手机登录步骤、展开列表、详情复制和账户设置。第三方 Google 的真实授权与生产邮件投递须在已配置的运行环境中验证；本地回归测试使用模拟供应商交换。
