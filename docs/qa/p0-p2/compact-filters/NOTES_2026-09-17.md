# Official、Skill 重复项、单行筛选与摘要入口

日期：2026-09-17。代码版本：a0ae435。此次代码先推送，再检查本地构建。

## 产品决定

1. 保留 Official：它提供已识别发布方的筛选入口，与 Trending、Rankings、Charts 是不同的查看方式。页面与标签说明明确它不是安全认证，不据此承诺资源质量。当前发布方识别规则仍有覆盖范围限制。
2. Skills 榜单按关联 GitHub 仓库分组：仓库 Star、Fork 和增长属于仓库，多个子 Skill 不应凭同一组指标连续占据多个名次。不同仓库仍独立，即使属于同一个组织。
3. 保留 Project age，桌面七项筛选同时展示。它帮助寻找新项目或较成熟项目，不代表质量。采集型 Skill 的日期来自关联项目，不能解释为 SKILL.md 首次发布的时间。
4. 每日摘要入口改为 Get started / 开始使用。按钮附近仍明确这是 Pro 功能，避免误以为免费。已有 Pro 用户继续看到管理邮件推送的入口。

## 重复项的处理范围

采集器原先以 SKILL.md 文件路径建立资源身份。同名 Skill 位于多个路径会产生多个资源；同一仓库的不同 Skill 也会重复展示相同的仓库指标。

现在先匹配筛选，再按精确仓库分组，最后排序和分页，返回总数是分组后的结果数。热度对比样本也按仓库计一次，避免文件多的项目重复影响对比基准。代表资源按路径与 ID 确定，输入顺序不会改变结果。

每组可以展开查看匹配 Skill 和文件路径。同名数量与文件路径数量分别展示，例如 2 个匹配 Skill、3 个文件路径。文件路径仍保留，并未根据相同名称判断文件内容完全一致或删除数据库记录。单组预览最多六个路径，其余通过详情中的资源入口查看。

此分组针对带 resourcePath 的采集型 Skill；没有文件路径的历史资源不会被猜测为同一个仓库资源。部署新 API 后可作用于已有采集数据，不要求清空数据库或重采。

## 筛选与布局

搜索、排序、时间窗口、语言、主题、用途、项目年龄在宽桌面同一行。缩短了排序名称和搜索提示，调整控件内边距，保留方框风格与点击高度。较窄屏幕按三列、两列、一列适配，手机不强制挤成一行。

修复非 Repository 类型忽略 age 参数的问题。30/90 天筛选使用实际经过天数，未知创建日期不作为新项目；测试覆盖 29.9 与 30.1 天边界。

Topic 描述技术或主题；Use case 描述用户要完成的任务，保留二者，并提供不同的说明。
