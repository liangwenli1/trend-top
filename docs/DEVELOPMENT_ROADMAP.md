## 产品边界

定位保持为跨六大类型的开源资源发现与持续情报。延续黑白、蓝色强调、方形控件风格；不扩展为 MCP 托管平台、通用自动化运行平台或广告门户。

Topic 描述技术与主题，例如 MCP、Python、数据库。Use case 描述用户要完成的任务，例如数据采集、代码协作。两者相关，但不互相替代；不因为新增 Use case 而降低其他筛选的可见性。

### P0-1：邮件增量口径

- 日增量缺失、异常时显示数据不足或待核实，不再用总 Star 填充增长图。
- 真实的零增长不制造最低宽度的增长条；负数使用明确的负数标签。
- 非仓库类型的条形图注明关联仓库指标，避免把仓库热度当作资源自身使用量。
- 邮件趋势图 URL 固定截止日期，后来采集的新日期不会使旧邮件窗口随时间移动。
- 趋势图文案注明累计新增 Star、UTC 与缺失日期不计。

剩余：图片仍从历史表生成，历史纠错可能改变旧图片；完整不可变邮件快照、图片内容哈希及资源自身指标的统一来源标识继续排期。

### P0-2：Pricing 信息与承诺

- 套餐权益、计费周期、功能介绍立即展示，仅金额等待接口。
- 前后端共享权益文案；增长图表限定为历史数据充足时可用。
- 移除面向普通用户的“等待管理员定价”。不可购买时展示通用可用性提示。
- 本语言没有定价时不启用购买按钮，避免其他语言定价造成误判。
- 管理员保存设置后清除服务端公共缓存；现有管理页同时清除当前浏览器的价格缓存。

### P0-3：采集与邮件独立调度

- 采集与发信各有独立任务槽，长时间采集不会占住发信调度。
- 每日 02:00 UTC 后检查采集，错过启动时刻可补执行；当日已完成的 ok/partial 采集可从数据库识别。
- 采集失败在后续小时重试，同一个调度进程不会并行重复采集。
- 发信在每个小时检查到期邮件；继续使用已有数据库领取机制与投递幂等设计。
- 停止调度进程时先终止子任务，超时再结束子任务。

剩余：独立槽不等于分布式任务队列。多副本采集锁、持久任务队列、积压与告警尚未完成；目前保持一个 scheduler 实例。

### P0-4：公共缓存与性能可见性

- 公开榜单、图表、筛选、搜索、详情和价格接口加入有界的服务端 JSON 缓存。
- 同一 URL 的同时请求合并；不同筛选与语言使用不同缓存项。
- 缓存最多 128 项、总计 8 MB、单项 512 KB，服务端有效期 60 秒。失败响应与私有账户、账单接口不缓存。
- 管理员后台展示最近 2,000 次请求的接口 P50/P95、数据库 P95、服务错误率以及缓存命中/合并统计，可手动刷新。

限制：缓存属于当前 API 进程，重启清空；独立采集进程的发布通过缓存到期反映。浏览器公共响应允许短期缓存，其他已打开客户端不会瞬时同步管理员改价。接口统计不覆盖浏览器下载、渲染与网络链路，尚未得出生产环境速度改善百分比。
